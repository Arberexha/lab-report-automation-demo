# Lab report workflow demo

A learning project that uploads a **fictional** PNG or JPEG lab-report image, forwards it to n8n, extracts text with an image model, and shows an educational model-generated discussion. This repository contains the React/Vite site and Express API. Configure the n8n workflow separately using [the workflow guide](docs/N8N_WORKFLOW.md).

This is a development demo, **not a clinical product**. OCR can confuse a measured result with a reference range, and generated text can be wrong. The app does not validate clinical findings or determine which medicine someone should take. Use fictional test images only. See [client-readiness notes](docs/CLIENT_READINESS.md) before considering real-world use.

## How it works

```text
Browser -> POST /api/cases -> Express -> private_uploads/
                                  |
                                  +-> authenticated n8n production webhook
                                      -> image transcription
                                      -> educational text model
                                      -> final JSON response
                                  |
Browser <- case ID + status + optional discussion
```

The API accepts one multipart file named `report`, up to 10 MB, with PNG or JPEG MIME type and matching file signature. It assigns a random case ID, stores the image outside the public site, and sends the image and case ID to n8n with the `x-webhook-secret` header. If n8n fails, the API removes that local upload. Successful uploads remain in `private_uploads/`; the demo has no deletion or retention process.

The site shows the response from **that upload request**. It has no case lookup or live polling. A page already showing `Processing` will not update after you change and publish the workflow; submit a new fictional image to test the change.

## Requirements

- Node.js 20.19+ or 22.12+
- npm
- An n8n instance with a published workflow
- An image-capable model connection in n8n for the optional OCR and discussion steps

## Local setup

```powershell
npm install
Copy-Item .env.example .env
```

Edit `.env`:

| Variable | Purpose |
| --- | --- |
| `N8N_WEBHOOK_URL` | The **Production URL** from your published n8n Webhook node, for example `https://YOUR-INSTANCE/webhook/lab-report-upload`. |
| `N8N_WEBHOOK_SECRET` | A long random value matching the n8n **Header Auth** credential. Keep it out of Git. |
| `PORT` | Express port; defaults to `3001`. |
| `UPLOAD_DIR` | Private upload directory; defaults to `./private_uploads` and must stay outside `dist/`. |

Run the site and API together:

```powershell
npm run dev
```

Open <http://127.0.0.1:5173>. Vite proxies `/api` to Express. For a production-style local run:

```powershell
npm run build
npm start
```

Then open <http://127.0.0.1:3001>.

The URL in `.env.example` points to a local n8n instance as a placeholder. Copy your own production webhook URL into `.env`. n8n's test URL (`/webhook-test/...`) is only for an active test listener and is not the URL to use for the published workflow.

## Configure n8n

Follow [docs/N8N_WORKFLOW.md](docs/N8N_WORKFLOW.md) for the exact node order, binary field name, expressions, prompts, and response settings. The final node must return JSON with:

```json
{
  "caseId": "the case ID received by the webhook",
  "ocrStatus": "completed",
  "demoDiscussion": "educational text generated by the model"
}
```

The API checks that the returned case ID matches the upload. When `ocrStatus` is `completed` and `demoDiscussion` contains text, the site displays **Learning discussion ready**. A final response with `transcription` instead of `demoDiscussion` displays an **unverified transcription**. An immediate or unrecognized n8n response displays **Processing**. An `ocrStatus` without usable text displays **Review needed**.

## Verify the connection

With `npm run dev` or `npm start` running, use fictional test data:

```powershell
npm test
npm run build
npm run check:n8n
npm run verify:webhook
```

- `npm test` tests upload validation, forwarding, status mapping, and cleanup against a webhook stub.
- `npm run build` checks that the frontend bundles.
- `npm run check:n8n` posts a blank fictional PNG directly to the configured n8n webhook and prints its HTTP status.
- `npm run verify:webhook` posts a blank fictional PNG through the local API and checks for a case ID and an accepted status. This blank image is a connectivity check; it is not a useful lab report for the models.

For an end-to-end test, submit a **fictional report image** in the browser, then match the displayed case ID to the n8n execution. Confirm the final node returned the fields above. If the page shows `Processing`, see the [troubleshooting section](docs/N8N_WORKFLOW.md#troubleshooting).

## Repository and security notes

`.gitignore` excludes `.env`, `private_uploads/`, `node_modules/`, build output, and the local npm cache. Review staged files before pushing. The image, OCR text, and model output still pass through your configured n8n and model services. Do not upload real patient reports to this demo or commit report images, credentials, or execution exports containing personal data.

Git is initialized locally, but this folder does not yet have a commit or a saved GitHub remote. After reviewing the files, run:

```powershell
git add .
git status --short
git commit -m "Document lab report workflow demo"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/YOUR-REPOSITORY.git
git push -u origin main
```

Replace the URL with your own repository. Confirm `git status --short` does **not** list `.env` or `private_uploads/` before committing.
